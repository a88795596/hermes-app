# Hermes 移动端实施计划

> **执行智能体**应使用分配的工作包、契约测试夹具和验收用例。实施时使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`。

**目标** — 让多个智能体在独立工作区并行实现和验收 Hermes 移动端的 iOS、Android、BFF、连接器与主动投递能力。

**架构** — 应用通过独立移动端 API 写入，通过持久事件流同步。连接器主动出站，隔离 Hermes Canonical Gateway、本地暂存和投递插件。

**技术栈** — pnpm、TypeScript、Expo SDK 58、React Native 0.88、Fastify 5、PostgreSQL、S3 兼容存储、SQLite 与 Python。

**规格** — [双平台技术设计](../specs/2026-11-13-hermes-mobile-design.md) · [移动端与连接器契约基线](../specs/2026-11-13-hermes-mobile-contracts.md) · [v2 验收用例原文 AT-01–30](../../reference/hermes-expo-engineering-spec-v2.md#182-必测用例)。

## 全局约束

- iOS 与 Android 同阶段交付核心功能并提交各自真机证据。无 GMS 通知能力单独验收。
- `packages/protocol` 维护对外 DTO 和数据结构定义，`packages/hermes-adapter` 维护固定 Hermes 版本的上游输入。应用只消费移动端契约。
- Hermes 主机票据、文件路径和主机权限留在连接器。HTTPS/WSS、SQLite 持久化确认、租户复合外键、同业务 ID 的重试是跨模块约束。
- 先验证失败用例再实现，真实 PostgreSQL、SQLite、对象存储、隔离 Hermes 和真机按表验收。夹具联调与真实联调分别记录。
- 设计交接起点是现有 pnpm 骨架。现有命令为 `pnpm typecheck` 和 `pnpm test`，其中现有自动测试是 BFF 健康检查。各工作包随实现增加所列测试入口并验证根命令能发现它们。

| 共享面 | 唯一写入者 | 其他智能体的交接方式 |

| 应用根布局、`app.json`、配置插件、原生模块注册 | W01 构建负责人 | 路由在各域目录实现；组合、权限配置、清单和原生依赖由构建负责人合入。 |

分支由集成负责人从同一已审阅的初始化基线分出，每个智能体在独立工作区只改其授权目录。新增路由按功能划分。共用文件变更交对应负责人串行合入。跨模块 API 变化先更新契约和兼容向量，再更新消费者。每包交接包含产物路径、契约和测试夹具版本、复现命令、测试输出及仍阻塞的能力。

每包使用 v2 §18.2 的 AT 场景作为测试输入与通过标准。按其建议路径或本仓库已用的同域路径落测试。纯 TypeScript 测试与服务测试接入各包 `test` 并由根 `pnpm test` 发现。真实依赖测试和双平台真机脚本随工作包发布，记录所需依赖、命令和退出条件。W09 独立在 Python 项目提供 `python -m unittest discover -s tests` 入口，集成报告单列结果。

## 审查重点

- 带相同标题的两个独立话题应建立不同 Hermes 绑定，旧创建回执丢失时，用同一请求恢复原绑定。W03 加隔离回归。
- 无 admission_id 的恢复窗口必须校验认证主体、绑定、负载和期限，超窗保持 `unknown`。W03 纳入 AT-05/06。
- WebSocket 确认之后重启能读到已应用状态，撤权不能继续下载旧快照。W04 与 W02 纳入 AT-08/10/19。
- 另一客户端或超时关闭服务端请求 时，本设备未获答案采用证据，应展示结束且结果不明。W06 纳入 AT-14。
- 上游暂存只允许实测过的 MIME 类型和目录，操作系统提供的临时 URI 只在本机打开。W07/W10 纳入 AT-20/22。
- 同一次定时任务执行中发生多次合法投递，或同文运行两次必须保留各自结果。W09 纳入 AT-25。
