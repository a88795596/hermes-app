# 实时语音输入实现计划

**目标：** 输入框右侧点击麦克风开始实时转写，再次点击或发送消息停止录音。

**实现：** 复用 assistant 的 sherpa-onnx 中文离线识别模块。原生模块负责麦克风、增量识别、尾音排空和音频中断；聊天 hook 将累计识别文本合入开始前的草稿；现有消息队列继续负责发送。无需修改 Hermes、BFF 或共享通信协议。

**范围：** 原生模块及模型准备脚本、原生构建入口、麦克风权限、聊天 hook、输入框按钮、回归测试和移动端说明。用户确认同时支持 iOS 和 Android；Android 使用同版本 sherpa-onnx AAR 和相同离线模型补齐原生录音。保留中文 UI，模型和引擎固定校验值，二进制不提交 Git。

## 行为约定

- 每次结果替换当前录音段，保留已有草稿；录音时锁定手动编辑，停止后恢复。
- 再次点击只停止，不发送；发送等待原生 `stop(id): Promise<string>` 返回最终累计文本。
- 启动或结束中的重复点击不创建多个录音/发送请求；空转写不发送空消息。
- 失去页面焦点、进入后台、切换话题或销毁时释放麦克风，忽略旧会话结果。
- 权限拒绝、系统中断和识别错误保留已识别草稿；未包含原生模块的旧包不显示按钮。

## 验证结果

- `pnpm typecheck`、移动端 lint 通过；`pnpm test` 272 项通过、10 项因未配置测试数据库跳过。
- iOS 模拟器 Debug 整包编译和链接通过；模型 bundle 的四个文件 SHA-256 与源资源一致。官方中文 WAV 实际推理通过增量、端点累积、最终排空及 48 kHz 重采样检查。
- Android arm64 Debug APK 构建与 Gradle 单元测试 2/2 通过；APK 内四个模型 SHA-256 一致，JNI 存在，16 KiB ZIP 对齐检查通过。测试依赖下载曾受 Google Maven 超时影响，本次构建通过临时 init script 让 JUnit/Hamcrest 直接使用官方 Maven Central，未更改正式仓库配置。
- 20 项固定资源校验、EAS 归档过滤、最终原生麦克风权限、平台指纹回归通过。
- 实际输入框组件在 320/390 px 下完成模拟录音状态的布局截图检查；未安装到用户手机，未测真实麦克风、蓝牙或来电中断。Android 无连接设备，现有 AVD 缺系统镜像，未执行 Android 真推理。
