# 无限会话流 · UI 稿（第二版）

日期：2026-11-17

第二版 imagegen UI 稿已确认，并已完成移动端实现。无限会话流默认关闭。

## 页面

1. [统一设置中心：默认关闭](01-settings-center-v2.png)：由聊天页右上角齿轮进入，集中「聊天」「收件箱」、当前会话设置和应用设置。「无限会话流」保持默认关闭；不增加二级功能描述。
2. [开启后首次进入](02-first-entry-v2.png)：直接进入已经准备好输入的空会话。左上角显示当前 Profile 头像，中间显示 Profile 名称，右上角进入统一设置中心；没有返回列表和新建会话按钮。底部仅保留输入栏和系统安全区。
3. [左右滑动切换 Profile](03-profile-swipe-v2.png)：用两个 Profile 的独立聊天内容示意切换前后；取消两页底部 Tab，输入栏下移。标题下的圆点表示当前位置。图外的箭头和文字为交互标注，不进入实际 App。

## 已实现的交互

- 每个 Profile 对应一条持续会话，首次使用自动创建，切换回来继续原会话。开关与会话 ID 存入当前设备配对范围内的 SQLite 缓存，关闭再开启不会重复创建。
- 按用户第二轮要求，开启后取消底部 Tab，导航入口收归右上角设置中心。原来的「话题」首页由聊天页取代；关闭设置中心或点击其中的「聊天」即可回到聊天页。
- 左上角使用项目已有的 ProfileAvatar，优先展示配置头像，缺省时使用名称首字；稿中的「日」「研」为缺省头像示例。
- 右上角齿轮打开统一设置中心：「聊天」「收件箱」为导航入口；「当前会话」包含模型和思考强度；「应用」包含无限会话流开关、配置档案、管理、连接、已归档会话和版本信息。
- 关闭后回到原有话题列表导航。本次未设计或执行任何历史会话删除操作。
- 头像支持点击选择 Profile；横划限定在聊天记录区域，输入栏不参与。录音、选择附件、发送和原生命令弹层期间禁用切换。
- 本地会话 ID 读写失败可刷新重试；网络请求失败继续使用同一 ID。服务端明确返回创建失败时，点击「恢复会话」并确认后归档原会话再连接，保留原有记录、草稿与待发消息。

## 样式依据

读取了 apps/mobile/src/ui/theme.tsx、ui/page-header.tsx、workspace-screen.tsx、chat/conversation.tsx、chat/settings-drawer.tsx、profiles/avatar.tsx，并参考仓库 output/profile-personalization 下的现有界面截图。

本稿展示浅色模式，沿用背景 #F7F2EA、正文 #352820、强调色 #86553B、消息底色 #EBDDD0；保留简洁列表、居中标题、附件在输入框内与语音在右侧框外的布局。
